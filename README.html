receipt-checker

When an AI agent says “done, all tests pass”, this reruns the proof from the exact commit, in a clean copy. If the proof doesn’t come out the same, the claim is refused.

A small command, receipt-check. Linux and macOS, Node.js 20 or later, no dependencies.

Full details: README.mdLicence: FSL-1.1-MITVersion 0.1.0

What happens when you check a receipt

  1. Read the receiptStrictly. Every mistake is shown with its line.
  2. Find the commitThe exact one it names. A branch name isn’t enough.
  3. Copy only that commitInto an empty folder: no stray files, no history.
  4. Rerun every checkWith a time limit and a clean environment.
  5. CompareWhat was claimed against what just happened.
✓ VERIFIEDEverything came out the same.exit 0
✗ REFUTEDSomething it claimed is false.exit 1
? INCOMPLETESomething couldn’t be checked, so it is not a pass.exit 2

The tricks it catches

REFUTED

“It passes on my machine”

The test needed a file that was never committed. The clean copy holds only the commit, so the test fails there.

REFUTED

“10 passed” when 9 ran

It counts the tests itself, from the TAP or JUnit report the rerun writes.

REFUTED

A failure hidden in a pipe

Every check runs in strict bash, so false | cat fails the way it should.

REFUTED

A commit that isn’t there

The id it names has to exist in the repository.

REFUTED

A test hidden from the copy

Files come straight from git, so .gitattributes can’t leave a failing test out.

INCOMPLETE

A check that hangs, or leaves no report

The time limit stops it and everything it started. Missing proof is never a pass.

  • Which commitThe full id, exactly as git prints it.
  • What to rerunEach check is a shell command, rerun in the clean copy.
  • What it claimsHow many tests passed, failed and were skipped.
  • What was deliveredFiles that must exist at that commit.
  • What was promisedEach promise names the check that proves it.

An optional log that shows edits

Each verdict can be added to a log. Every entry carries a fingerprint of the one before it, so changing an old entry breaks the chain right there.

Entry 1VERIFIED
→
Entry 2, editedfingerprint no longer matches
→
Entry 3points at the old entry 2

It shows tampering; it can’t prevent it. Someone who can write the file can rewrite the whole chain, so keep the latest fingerprint somewhere they can’t.

Know this before you run it

  • It runs the commands in the receipt. The clean copy is not a sandbox. Read a receipt before you check it, as you would a script.
  • A check proves only what it tests. A receipt whose only check is true passes.
  • Checks have the network unless you ask for --offline, which works on Linux only. Elsewhere it says INCOMPLETE instead of quietly running online.
  • Linux and macOS only. It doesn’t run on Windows.
